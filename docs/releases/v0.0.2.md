# KL4A v0.0.2

**v0.0.2 expands KL4A beyond SOP knowledge bundles with a Rust workspace and
the first CodeKB documentation set.**

## Highlights

**Rust workspace.** The repository now includes `v2/kl4a-rs/`, with the shared
`kl4a-core` crate, the `codekb` crate and binary, and the unified `kl4a`
dispatcher. This establishes the Rust implementation as the foundation for
ongoing CodeKB work.

**Code Knowledge Bundles.** CodeKB turns a source repository into a grounded,
reviewable knowledge bundle. It inventories supported files, extracts modules,
symbols and relations, records source evidence, and exposes the resulting bundle
through command-line and MCP read surfaces.

**Expanded documentation.** The documentation now includes CodeKB guides for
its pipeline, architecture, bundle state, knowledge and review model, agent
consumption, MCP integration, and a real validation case study. The KL4A
walkthrough also shows how the same knowledge-layer approach applies to both
SOPs and source repositories.

**Documentation continuity.** Existing SOPKB guidance, reference material,
examples, and evidence-first product narrative remain part of the release. The
new material extends that story; it does not replace the SOP workflow.

## What remains true

KL4A remains local-first and evidence-led: source material is turned into
plain, inspectable knowledge bundles, and source evidence remains available to
the people and agents using those bundles.

## Current boundaries

- SOPKB remains the complete, human-reviewable SOP workflow.
- CodeKB is an evolving Rust implementation; use the published documentation
  to understand its supported source scope and operational boundaries.
- Bundle formats continue to evolve independently of the software version.
  See the [OKF Bundle Specification](../OKF_BUNDLE_SPEC.md) and
  [Bundle Compatibility Policy](../BUNDLE_COMPATIBILITY_POLICY.md).
